# UI: редизайн создавателя и редактора

Бриф для отдельной сессии. Логика, API и поведение уже готовы и покрыты тестами. Задача: сделать интерфейс уровня
внутреннего инструмента крупной компании: спокойный, плотный, точный, с продуманными мелочами. Перед работой прочитай
[CLAUDE.md](../CLAUDE.md) и [PLAN.md](../PLAN.md), раздел «Логика редактора»: это спецификация поведения, её не меняем.

Скиллы: `unslop` (направление и чистка), `frontend-ui-engineering` (компоненты, состояния, доступность),
в конце `design:accessibility-review`.

## Жёсткие ограничения

- **Стек не меняем.** Jinja2-шаблоны и vanilla JS (или jQuery, как сейчас в редакторе), без сборщика, React и Tailwind.
  Стили — обычный CSS на токенах (custom properties).
- **Подписи из ТЗ и эталонного видео не трогаем:** `Name`, `Geo`, `Offer`, `Create`, `Fetch streams from KT`,
  `View in KT`, `Add offer`, `Push`, `Cancel`, `Remove`, `Bring back`, `Pin`. Пояснения, подсказки и ошибки
  остаются на русском. Если по дизайну хочется переименовать кнопку или изменить поведение из видео, сначала спроси.
- **Семантика из видео сохраняется:** поток с неопубликованными правками жёлтый (янтарный), удалённый оффер серый,
  доля 0%, у него кнопка Bring back. Оттенки можно облагородить, смысл цвета менять нельзя.
- **Keitaro боевой и общий.** В превью нельзя нажимать Fetch, Add offer, Push и Create против настоящего трекера.
  Как проверять безопасно, описано в разделе «Проверка».
- Нельзя ломать `same_origin_only`, `TrustedHostMiddleware`, контракт JSON API и тесты. `python -m pytest` и `ruff check .`
  должны оставаться зелёными. Тест `test_offer_search_and_index_page` ищет на `/` текст «New campaign».
- **Реальные данные трекера не попадают в git:** ни в скриншоты, ни в фикстуры, ни в примеры. Сейчас `docs/editor.jpg`
  содержит настоящие названия офферов и id кампании, его нужно заменить скриншотом на демо-данных.

## Характер и визуальная система

Ориентир по ощущению: плотные рабочие инструменты вроде Stripe Dashboard или Linear, но без их брендинга.
Много воздуха между группами, мало его внутри строк. Цвет почти только служебный: акцент, статусы, ошибки.

**Шрифты.** IBM Plex Sans для интерфейса и IBM Plex Mono для id, кодов стран и alias. У обоих есть кириллица,
лицензия OFL. Файлы woff2 (latin + cyrillic, начертания 400/500/600) положить в `app/static/fonts/` и подключить
через `@font-face` с `font-display: swap` и `preload` для основного начертания. Google Fonts не подключать:
приложение должно работать без внешних запросов. Скачивание файлов шрифтов согласуй с пользователем.
Для долей и итогов — `font-variant-numeric: tabular-nums`, чтобы цифры не прыгали при пересчёте.

**Шкала шрифтов:** 12 / 13 / 14 (основной) / 16 / 20 / 24. Межстрочный 1.45 для текста, 1.2 для заголовков.
Заголовки — начертание 600, без капса и разрядки.

**Цвета** (стартовые значения, подбери точнее; контраст текста не ниже WCAG AA 4.5:1):

| Токен | Значение | Где |
|---|---|---|
| `--bg` | `#f5f6f8` | фон страницы |
| `--surface` | `#ffffff` | карточки потоков, формы |
| `--surface-2` | `#f0f2f5` | шапка таблицы, hover строки |
| `--border` / `--border-strong` | `#e2e5ea` / `#c9ced6` | разделители / поля ввода |
| `--text` / `--text-2` / `--text-3` | `#15181e` / `#464d5b` / `#6b7280` | основной / вторичный / приглушённый |
| `--accent` / `--accent-hover` / `--accent-soft` | `#1f45c8` / `#1838a6` / `#ebf0ff` | основная кнопка, ссылки, фокус |
| `--draft-bg` / `--draft-border` / `--draft-text` | `#fff7e0` / `#e6c15a` / `#7a5200` | неопубликованный поток |
| `--danger` / `--danger-soft` | `#c0362c` / `#fdecea` | ошибки, итог ≠ 100% |
| `--success` / `--success-soft` | `#1d7a4b` / `#e6f4ec` | «Опубликовано» |

Тёмная тема по желанию: токены переопределяются в `@media (prefers-color-scheme: dark)`.

**Сетка и формы.** Шаг отступов 4px (4/8/12/16/24/32/48). Радиусы 6px для полей и кнопок, 8px для карточек.
Тени только у всплывающих элементов (список автокомплита, диалог, тост), у карточек вместо теней рамка 1px.

**Иконки.** Inline SVG одного набора (например, пути Lucide, лицензия ISC), 16px, обводка 1.5. Нужны: обновить (Fetch),
внешняя ссылка (View in KT), плюс (Add offer), булавка (Pin), вернуть (Bring back), предупреждение, галочка.
Никаких эмодзи и иконочных шрифтов.

**Анимации.** Длительность 150–220 мс, кривая `cubic-bezier(.2, 0, 0, 1)`, без пружин и отскоков. Анимируем:
- смену доли: число плавно перетекает от старого значения к новому, полоска доли меняет ширину;
- подсветку изменившихся долей после пересчёта: короткая вспышка фона ~600 мс, чтобы было видно, что задел rebalance;
- появление новой строки оффера (fade + сдвиг на 4px) и переход строки в серое состояние при Remove;
- переход потока в жёлтое состояние и обратно (цвет фона и рамки);
- открытие списка автокомплита, диалога, появление и уход тоста.

`prefers-reduced-motion: reduce` отключает движение и оставляет только мгновенную смену состояний.

## Чего не делать

Фиолетовые и индиго-градиенты, градиентный текст, свечения, стекло и размытые пятна на фоне, эмодзи в подписях,
бейджи «New ✨», капс с разрядкой на каждой подписи, пульсирующие точки, большой центрированный герой-блок,
скругления по 16–24px, тени на всём подряд, каждая мелочь в отдельной карточке, Inter «по умолчанию»,
приветственные тексты вроде «Добро пожаловать!», декоративные иллюстрации.

## Каркас

- `app/templates/base.html` (Jinja `extends`): `<head>`, шрифты, `app/static/app.css`, `app/static/app.js`, шапка.
  Сейчас стили продублированы внутри двух шаблонов, их нужно вынести.
- `app/main.py`: смонтировать `StaticFiles` на `/static`. Это GET, middleware не мешают.
- Шапка: название продукта, навигация «Новая кампания» и «Кампании» и неброский чип с хостом подключённого трекера
  (берётся из `settings.keitaro_url` при рендере, в код и документы адрес не писать). Чип напоминает, что действия
  уходят в общий боевой Keitaro.
- Общие компоненты в `app.js` и `app.css`:
  - **Кнопки** primary / secondary / ghost / danger. У каждой есть состояние загрузки (спиннер, ширина не меняется)
    и disabled с причиной в подсказке.
  - **Поле**: label, подсказка, текст ошибки под полем, `aria-describedby`, `aria-invalid`.
  - **Бейдж статуса**: «Активен», «Удалён», «Новый», «Не опубликовано», «Только просмотр».
  - **Тосты** в `aria-live="polite"`, ошибки в `role="alert"`. Тост успеха исчезает сам, ошибка остаётся до закрытия.
  - **Диалог подтверждения** на нативном `<dialog>` через `showModal()`: фокус-ловушка, Esc закрывает, фокус после
    закрытия возвращается на кнопку, которая открыла диалог.
  - **Комбобокс офферов** по паттерну ARIA 1.2 вместо `<datalist>`. Нативный datalist по-разному выглядит в браузерах,
    его нельзя оформить, а id приходится выковыривать из текста через `parseInt`.
    - Выбранный оффер хранится явно (`data-offer-id`), а не разбирается из подписи.
    - Стрелки, Enter, Esc, Home и End; `aria-activedescendant`; подсветка совпадения в названии.
    - Состояния «Ищу…», «Ничего не найдено» и ошибка Keitaro с кнопкой «Повторить».
    - Запрос с задержкой 250 мс, предыдущий отменяется через `AbortController`, чтобы поздний ответ не затёр свежий.
    - id в моноширинном шрифте. Если название уже начинается с id, второй раз его не выводить.
  - **Пустые состояния и скелетоны** вместо голого текста «Пока нет».
- **Единый `api()`-хелпер** с разбором ответа:
  - `detail` бывает строкой или списком (ошибка валидации pydantic). Сейчас список превращается в `[object Object]`.
  - 409 (поток изменён в Keitaro) — плашка у потока с кнопкой `Fetch streams from KT`.
  - 403 — режим «только просмотр».
  - 422 — ошибка рядом с полем или потоком, к которому она относится.
  - 502 — текст ошибки Keitaro и кнопка «Повторить».
  - Сетевая ошибка — понятное сообщение без технического мусора.

## Страница «New campaign» (`/`)

Раскладка на десктопе: форма слева (около 420px), список кампаний справа. На мобильном они идут друг под другом.

- **Name.** Под полем живой предпросмотр итогового имени: `test_Zaitsev_` приглушённо, введённая часть обычным цветом.
  Префикс приходит из `settings.name_prefix`, он уже передаётся в шаблон.
- **Geo.** Ввод кодов чипами: запятая, пробел или Enter превращают код в чип, Backspace удаляет последний.
  - У чипа код моноширинным и название страны через `Intl.DisplayNames(['ru'], {type: 'region'})`.
  - Проверка по тому же списку, что на бэкенде: передать `services.COUNTRIES` в шаблон как JSON.
    Неверный чип красный с пояснением, на `UK` подсказка `GB`.
  - `Intl.DisplayNames` для проверки не годится: для `UK` он может вернуть «Великобритания», хотя бэкенд такой код не примет.
- **Offer.** Комбобокс из каркаса. После выбора показывается карточка оффера: id, полное название, кнопка «сменить».
- **Create.**
  - Кнопка disabled, пока форма неполная, с подсказкой, чего не хватает. Во время запроса состояние загрузки
    («Создаю кампанию…»), повторное нажатие невозможно.
  - Успех: карточка результата с именем, id, alias (с кнопкой копирования), оффером из ответа (`data.offer`) и
    ссылками «Открыть в редакторе» и `View in KT`. Новая строка анимированно появляется в списке справа.
    Перезагрузку страницы через 1.5 с (как сейчас) убрать.
  - Ошибка: значения формы сохраняются. 422 по Geo или имени показывается у поля, 502 — плашкой с текстом Keitaro.
- **Открыть по id.** Поле с `inputmode="numeric"`, Enter открывает редактор, нечисловой ввод не принимается.
- **Список кампаний:** id моноширинным, имя, Geo чипами, дата создания (`Intl.DateTimeFormat`), бейдж
  «Только просмотр» для кампаний без префикса, ссылка в редактор по всей строке. Пустое состояние объясняет,
  что сюда попадают созданные и загруженные через Fetch кампании.

## Редактор (`/campaigns/{id}`)

- **Шапка:** имя кампании, id моноширинным с копированием, бейдж «Только просмотр» для чужих, справа
  `Fetch streams from KT` (secondary с иконкой) и `View in KT` (ссылка с иконкой внешней ссылки).
  Заголовок вкладки `document.title` совпадает с именем кампании.
- **Fetch:** если есть неопубликованные потоки, сначала диалог: «Неопубликованные правки в N потоках будут сброшены».
  После Fetch тост «Загружено из Keitaro».
- **Кампания ещё не загружена** (ответ 404): пустое состояние с объяснением и крупной кнопкой Fetch вместо строки текста.
- **Поток без офферов:** компактная строка с позицией, именем и пометкой «Поток без офферов», без таблицы. Как в эталоне.
- **Поток с офферами** — карточка:
  - Шапка: позиция, имя; при наличии правок янтарный фон, рамка и бейдж «Не опубликовано · N изменений».
  - Таблица: Offer (id моно и название), Share (число и тонкая полоска доли), State (бейдж), Pin, Actions.
    - Длинные названия (реальные бывают длиннее 100 символов) обрезаются в две строки, полное название в `title`.
    - Удалённые строки приглушены, доля 0%, вместо Remove кнопка Bring back. Порядок строк не меняем
      (сейчас это порядок добавления); если хочется вынести удалённые в отдельный архив, сначала спроси.
    - Pin — кнопка-переключатель с иконкой булавки и `aria-pressed`, а не голый чекбокс. Если запрос упал,
      состояние откатывается к серверному (сейчас чекбокс остаётся переключённым).
  - Итог: «Итого 100%». Если итог не 100, он красный, рядом короткое объяснение «закреплено X%».
    Push в этом состоянии disabled, причина в подсказке.
    Не обещай, что снятие закрепления починит сумму: сейчас unpin доли не пересчитывает (пункт 6 аудита, не исправлен).
  - **Было → стало.** У изменённых строк приглушённо показывать опубликованную долю: `33% → 25%`.
    Новые офферы помечены «Новый», удалённые до публикации — «Будет убран из Keitaro».
  - Низ карточки: комбобокс и Add offer слева, Cancel (secondary) и Push (primary) справа. Push и Cancel активны,
    только когда есть правки. Enter в комбобоксе добавляет выбранный оффер.
  - **Push** открывает диалог со сводкой: какие офферы уйдут в Keitaro и с какими долями, что будет убрано.
    Отдельное предупреждение, если активных офферов не остаётся: «Поток останется без офферов». Это пункт 7 аудита,
    бэкенд такой Push пока пропускает. После успеха тост «Опубликовано в Keitaro», карточка плавно становится белой.
  - **Только просмотр:** у чужой кампании скрыть все элементы правки (Add offer, Remove, Pin, Push, Cancel),
    а не только Push. Сейчас локальные правки чужой кампании возможны, и это сбивает с толку.
- **Пока идёт запрос** кнопки этого потока заблокированы: сейчас двойной клик по Add offer может упереться в уникальный ключ.
  Ответ — всегда целая кампания с сервера, оптимистичных обновлений не делаем: доли считает сервер.
- **Перерисовка:** сейчас каждый ответ заново строит все потоки, теряются фокус, позиция прокрутки и текст в поле
  поиска. Нужно обновлять узлы по ключу (`data-stream-id`, `data-so-id`) или после рендера возвращать фокус
  и прокрутку. Для анимации долей держать предыдущее состояние `{so_id: share}` и считать разницу.
- Черновики хранятся в БД, поэтому предупреждение при уходе со страницы не нужно. Вместо него ненавязчивая подсказка
  в карточке с правками: «Черновик сохранён, в Keitaro ещё не отправлен».

## Мелочи, которые проверяют руками

- Видимый фокус (`:focus-visible`, кольцо цветом акцента) у всех интерактивных элементов, порядок табуляции логичный.
- Кликабельная область не меньше 32px на десктопе и 44px на тач-экранах.
- Цвет не единственный сигнал: у жёлтого потока есть бейдж с текстом, у удалённой строки есть статус словами.
- Никаких сдвигов макета: спиннер в кнопке не меняет её ширину, ошибки под полями не толкают соседние блоки.
- Числа и id в моноширинном или табличном начертании, проценты выровнены по правому краю.
- Копирование id и alias одним кликом с коротким «Скопировано».
- Ширина 375px без горизонтальной прокрутки страницы; таблица офферов на узком экране превращается в
  карточки строк или прокручивается внутри карточки потока.
- `favicon` (inline SVG), `<title>` на каждой странице, `lang="ru"`.

## Небольшие правки бэкенда, которые понадобятся (с тестами)

1. `StaticFiles` в `app/main.py` для `/static`.
2. `editor.serialize`: добавить в оффер `pub_share` и `pub_state` для «было → стало» и сводки Push.
3. В шаблон `/` передать `services.COUNTRIES` для проверки Geo на клиенте.
4. По желанию, **только после согласования**: колонка `campaigns.fetched_at` (миграция Alembic) и подпись

Всё остальное (`rebalance`, Push, Fetch, Cancel, проверки) не трогать.

## Проверка

- **Фейковый Keitaro.** В scratchpad (не в репозитории) поднять маленький FastAPI на `127.0.0.1:8765`, который
  отвечает на `/admin_api/v1/offers`, `/campaigns/{id}`, `/campaigns/{id}/streams`, `POST /campaigns`, `POST /streams`,
  `PUT /streams/{id}`. Данные выдуманные: 20–30 офферов с длинными названиями в духе реальных, одна своя кампания
  с префиксом и одна чужая. `PUT` меняет состояние, чтобы Push и повторный Fetch вели себя честно.
  Нужны ручки, которые возвращают 409-сценарий (поток изменён) и 502, чтобы проверить состояния ошибок.
- Превью запускать с переменными окружения, они важнее `.env`: `KEITARO_URL=http://127.0.0.1:8765`,
  `KEITARO_API_KEY=demo`, `DATABASE_URL=sqlite:///./ui_demo.db` (`*.db` уже в `.gitignore`), `DEFAULT_*` любые.
  Перед проверкой убедиться, что запросы уходят на фейковый сервер, а не в боевой трекер.
- Пройти сценарий из видео (Fetch → Add → Cancel → Add → Push → Remove → Push → Bring back → Pin) и сценарии ошибок
  (409, 422 по Geo, 502, итог ≠ 100%).
- Скриншоты на 1440 и 375 px, только клавиатура, `prefers-reduced-motion`, контраст, пустая консоль без ошибок.
- `python -m pytest`, `ruff check .`, `ruff format --check .`.
- Заменить `docs/editor.jpg` скриншотом на демо-данных и обновить README, если поменялись подписи или раскладка.

## Вне рамок

Пункты 5–8 аудита (авторизация, пересчёт при снятии pin, запрет Push пустого потока на бэкенде, откат создания
при не-HTTP ошибках) — отдельные задачи. UI только не должен вводить в заблуждение там, где они ещё не исправлены
(см. итог и диалог Push выше).
